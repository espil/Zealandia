# Espil Online: A to Zealandia - Capacitor App

This is the paid mobile app for Espil Online, built as a Capacitor wrap of the
current web game. Han chose this route on 2026-10-16: reuse the game that is
already built and verified, instead of a native rewrite.

• Store product: "Espil Online: A to Zealandia" (title decided by Han, 2026-10-21; paid, Google Play and Apple App Store)
• Web at espil.online stays free: the social and commerce hub
• This app is the game layer: battle first, housing after

## Store title - decided

Han decided the title on 2026-10-21: **"Espil Online: A to Zealandia"**
(28 characters, inside the 30-character store limit on both stores). The
earlier full phrase "Espil Online: Zealandia Extension Pack" is 38 characters

the Android strings, and the iOS display name all carry the decided title.

## Architecture

• **Web game, bundled.** `scripts/sync-web.mjs` copies the game from
  `~/workspace/espil-online-deploy/` into `www/`, and Capacitor bundles `www/`
  into the native app. The deploy copy is read-only source for this project:
  nothing here ever writes to it, and this project never deploys the website.
• **Places data via espil.online.** The game calls `/api/places-*` Vercel
  serverless proxies so the Google Places key stays server-side. The sync
  script rewrites those paths in the copied `www/index.html` only, to
  `https://espil.online/api/...`, and injects
  `window.__ESPIL_APP__ = true` and
  `window.__ESPIL_API_BASE__ = 'https://espil.online'` in the head.
• **Characters are remote assets, not bundle.** `assets/character/` is about
  338MB of GLBs in the web copy. Bundling that would blow up the store binary,
  so the default sync excludes it and leaves
  `www/assets/character/REMOTE-ASSETS.md` explaining the plan: characters ship
  as downloadable assets from object storage, matching the recorded plan to
  move the GLBs out of the repo. Run `npm run sync:full` only for local tests
  that need the characters in place.
• **Offline and keys.** The game's `fetch('/.env')` local-key flow simply
  finds no file inside the app and is handled gracefully by the game code; no
  key is ever bundled into the app.

## Places proxy gate - fixed in the sync patch (2026-10-16)

The game decides whether to use the Places proxies with a hostname test
(`PLACES_PROXY` is true only when the hostname is espil.online). Inside
Capacitor the hostname is localhost, so that test would be false and the
rewritten `https://espil.online/api/...` URLs would sit in the branch that
is not taken; the game would fall back to a direct Google Places call with
a placeholder key. The sync script now patches the app copy only:
`PLACES_PROXY` also returns true when `window.__ESPIL_APP__` is set (the
flag is injected in the head, before the game code runs). Verified after
sync: the patched line is present in `www/index.html` and in both native
asset copies (android and ios), the four Places URLs are the absolute
proxy URLs, and the shared web source is byte-untouched. Still to confirm
in a real device run: the proxied Places responses themselves.

## Build steps on Han's PC

Prerequisites: Node.js 20 or newer, npm, and Android Studio for Android.
iOS builds require a Mac with Xcode; they cannot be made on Windows.

1. Install dependencies:

   ```
   npm install
   ```

2. Copy the current web game into `www/`:

   ```
   npm run sync
   ```

   Use `npm run sync:full` instead only for a local test that needs the
   character GLBs bundled.

3. Add the Android platform (once; already done in this scaffold copy, so
   skip it if the `android/` folder is present):

   ```
   npx cap add android
   ```

4. Sync the web build into the native project (after every `npm run sync`):

   ```
   npx cap sync
   ```

5. Open and run from Android Studio:

   ```
   npx cap open android
   ```

   Or run the combined script: `npm run android` (sync plus open).

6. iOS, on a Mac only (the `ios/` project folder is already generated in
   this scaffold copy; building it still requires a Mac with Xcode):

   ```
   npx cap add ios
   npx cap sync
   npx cap open ios
   ```

## What this scaffold is not

• It is not a production release. Nothing here is pushed, deployed, or
  submitted to any store.
• The Android and iOS native projects are generated by `npx cap add` on the
  build machine; they are not hand-written here.
• A Gradle compile needs Java and the Android SDK from Android Studio, which
  the development VM does not have. Native builds happen on Han's PC.
